# LS1D 智能水表 MATLAB 仿真测试完整指南

## 📋 测试概览

本测试方案分为三个阶段，从纯软件仿真到硬件集成，再到实流标定，逐步验证智能水表系统。

| 阶段 | 名称 | 所需设备 | 预计时间 | 主要目标 |
|------|------|----------|----------|----------|
| 1 | MATLAB 仿真验证 | PC + MATLAB | 2-4 小时 | 熟悉算法，参数调优 |
| 2 | 硬件集成测试 | PC + LS1D 开发板 | 1-2 天 | 验证软硬件一致性 |
| 3 | 实流标定验证 | 完整测试台 | 3-5 天 | 参数标定，精度验证 |

## 🔌 阶段二：硬件集成测试

### 目标
- 验证 LS1D 开发板能正常进行超声测量
- 采集真实 TDC 数据
- 对比 MATLAB 和嵌入式计算结果
- 建立 Golden Vector 验证机制

### 前置条件
- ✅ LS1D 开发板已通电
- ✅ UART0 连接到 PC（115200 baud）
- ✅ 嵌入式程序已烧录
- ✅ 安装 Python 3.x + pyserial 库

### 硬件连接

```
LS1D 开发板          USB 转串口模块          PC
┌─────────┐          ┌──────────┐      ┌──────┐
│  UART0  │          │          │      │      │
│   TX ───┼─────────▶│ RX       │      │      │
│   RX ───┼──────────│ TX       │      │      │
│   GND ──┼─────────▶│ GND      │USB   │ COM3 │
│         │          │         ─┼─────▶│      │
└─────────┘          └──────────┘      └──────┘
```

**针脚定义（根据实际原理图确认）：**
- UART0 TX: GPIO_XX
- UART0 RX: GPIO_XX
- 波特率: 115200
- 数据位: 8
- 停止位: 1
- 校验位: 无

#### 2.1 修改嵌入式代码输出格式

// 在测量完成后输出数据
void output_measurement_data(uint32_t tof_down_ticks, 
                              uint32_t tof_up_ticks,
                              float temperature_c,

**输出格式：**

#### 2.5 Golden Vector 验证

**目的：** 确保 MATLAB 和嵌入式代码计算同一组输入时得到相同结果

**步骤：**
1. MATLAB 生成测试向量（`golden_vectors/matlab_golden.csv`）
2. 将 `tof_down_ticks` 和 `tof_up_ticks` 输入嵌入式代码
3. 嵌入式代码输出计算的流速和流量
4. 对比误差

**容差标准：**
- 速度误差 < 0.1%（定点运算精度损失）
- 流量误差 < 0.1%
- 如果误差 > 1%，需要检查：
  - TDC tick 周期是否正确
  - 物理参数是否一致
  - 定点运算是否溢出

## 💧 阶段三：实流标定与验证

### 目标
- 确定真实物理参数
- 标定 TDC 通道偏置和增益
- 验证测量精度符合要求
- 完成温度补偿

### 前置条件
- ✅ 完成阶段二硬件集成测试
- ✅ 有标准流量计（精度 ≤ 0.5%）
- ✅ 可控水流测试台
- ✅ 温度测量装置
- ✅ 水表已正确安装

### 测试台配置

```
水箱 → 水泵 → 流量调节阀 → 标准流量计 → 待测水表 → 回水箱
                                  ↓             ↓
                            标准值读数    LS1D测量值
```

### 操作步骤

#### 3.1 零流标定（确定通道偏置）

**目的：** 在静止水流中，理论上 `tof_down` 应等于 `tof_up`，实际偏差即为系统偏置

**步骤：**
1. 关闭水泵，确保管道内水完全静止
2. 等待 5 分钟让系统稳定
3. 采集 5-10 分钟数据
   ```bash
   python capture_uart_data.py --port COM3 --duration 600 --output ../calibration_data/zero_flow_test.csv
   ```
4. 分析数据
   ```matlab
   run('../测试方案/test_phase3_calibration.m')
   ```
5. 记录偏置值并更新配置

**记录表：**
| 项目 | 数值 | 单位 |
|------|------|------|
| 平均 TOF_down | | ticks |
| 平均 TOF_up | | ticks |
| 时差 | | ticks |
| 偏置（秒） | | ns |
| 偏置（米） | | mm |

#### 3.2 标准流量点标定

**测试流量点：** 0.5, 1.0, 2.0, 5.0, 10.0 L/min（根据水表量程调整）

**每个流量点操作：**
1. 调节阀门设置目标流量
2. 等待流量稳定（观察标准流量计）
3. 同时记录：
   - 标准流量计读数
   - LS1D 开发板输出
   - 水温
4. 采集 3-5 分钟数据
   ```bash
   python capture_uart_data.py --port COM3 --duration 180 --output ../calibration_data/flow_2.0_lpm.csv
   ```

**记录表：**
| 标准流量 (L/min) | 测量流量 (L/min) | 相对误差 (%) | 水温 (°C) | 备注 |
|-----------------|-----------------|-------------|-----------|------|
| 0.5             |                 |             |           |      |
| 1.0             |                 |             |           |      |
| 2.0             |                 |             |           |      |
| 5.0             |                 |             |           |      |
| 10.0            |                 |             |           |      |

#### 3.3 温度补偿验证

**目的：** 验证声速-温度补偿模型

**步骤：**
1. 在固定流量（如 2.0 L/min）下
2. 改变水温（10°C, 20°C, 30°C）
3. 观察测量流量是否稳定

**记录表：**
| 水温 (°C) | 测量流量 (L/min) | 标准差 | 相对标准差 (%) |
|-----------|-----------------|--------|----------------|
| 10        |                 |        |                |
| 20        |                 |        |                |
| 30        |                 |        |                |

**期望结果：** 相对标准差 < 1%

#### 3.4 长期稳定性测试

**步骤：**
1. 设置固定流量 2.0 L/min
2. 连续运行 1-2 小时
3. 记录累计体积

**记录表：**
| 测试时长 (min) | 标准累计 (L) | 测量累计 (L) | 绝对误差 (L) | 相对误差 (%) |
|---------------|-------------|-------------|-------------|-------------|
| 60            |             |             |             |             |

#### 3.5 精度等级评定

根据 GB/T 778.2-2018《冷水水表》标准：

| 精度等级 | Q1 误差限 | Q2-Q4 误差限 |

### 问题排查

#### 问题 1：有效率很低（< 80%）
**可能原因：**
- 门控窗口设置不当
- 换能器安装问题
- 信号质量差

**排查方法：**
- 检查 `valid_down` 和 `valid_up` 标志
- 观察 TOF 值是否在合理范围
- 检查硬件连接

#### 问题 2：测量值与标准值偏差大（> 5%）
**可能原因：**
- 物理参数不准确（管径、声程、角度）
- TDC 标度错误
- 流速剖面系数不对

**排查方法：**
- 重新测量物理尺寸
- 检查 `cfg.tdc.tick_period_s`
- 做多点线性拟合

#### 问题 3：温度变化时误差变大
**可能原因：**
- 声速温度补偿模型不准确

**排查方法：**
- 重新标定声速-温度关系
- 增加更多温度点测试

## 🔧 嵌入式代码修改建议

为了更好地配合 MATLAB 测试，建议对嵌入式代码做以下增强：

### 1. 添加调试输出模式

```c
// main.c 或配置文件
#define DEBUG_OUTPUT_MODE 1  // 1: CSV格式, 0: 普通模式

#if DEBUG_OUTPUT_MODE
    void output_measurement_csv(measurement_t *meas) {
        printf("MEASURE,%u,%u,%.2f,%u,%u\n",
               meas->tof_down_ticks,
               meas->tof_up_ticks,
               meas->temperature_c,
               meas->valid_down,
               meas->valid_up);
    }
#endif
```

### 2. 添加统计信息

```c
typedef struct {
    uint32_t total_measurements;
    uint32_t valid_measurements;
    uint32_t timeout_count;
    uint32_t outlier_count;
    float avg_flow_lpm;
} measurement_stats_t;

void print_stats(measurement_stats_t *stats) {
    printf("STATS: total=%u, valid=%u, rate=%.2f%%\n",
           stats->total_measurements,
           stats->valid_measurements,
           100.0f * stats->valid_measurements / stats->total_measurements);
}
```

### 3. 添加 Golden Vector 测试模式

```c
// 用于验证算法实现
#define GOLDEN_VECTOR_TEST 0

#if GOLDEN_VECTOR_TEST
const uint32_t test_tof_down[] = {67500, 67505, 67502, ...};
const uint32_t test_tof_up[] = {68200, 68195, 68198, ...};

void run_golden_vector_test() {
    for (int i = 0; i < TEST_VECTOR_SIZE; i++) {
        float velocity = calculate_velocity(test_tof_down[i], test_tof_up[i]);
        printf("GV,%d,%.6f\n", i, velocity);
    }
}
#endif
```
