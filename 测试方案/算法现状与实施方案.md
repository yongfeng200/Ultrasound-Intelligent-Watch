# LS1D 智能水表算法现状与实施方案

## 1. 文档目的

本文说明当前 `1.gpio_led_control_demo` 工作区中已经具备的算法、尚未具备的功能，以及从 LED 示例工程逐步实现超声波智能水表测量的建议流程。

本文结论基于当前工作区文件结构、源码以及实物开发板检查结果，适用于：

- MATLAB 仿真验证；
- 带 USB Type-C 接口的 LS1D 开发板超声波/TDC 底层测量；
- 上层流速、流量、滤波和累计体积算法移植；
- 通过板载 USB Type-C 串口进行数据采集；
- 后续参数标定和重新烧录。

---

## 2. 结论摘要

当前工程不是完整的智能水表应用，而是一个 **GPIO LED 控制 Demo + 超声波测量底层驱动库**。

### 当前已经具备

- 超声波测量硬件寄存器配置；
- TDC 底层时间转换；
- 顺流、逆流 TOF 读取和时差处理；
- TDC 自动校准和门控窗口配置；
- 超时、AFE、发射脉冲和接收链路配置；
- MATLAB 端完整的算法仿真和数据回放工具。

### 当前尚未完整具备

- 在嵌入式主循环中启动并读取一次超声波测量；
- 将嵌入式测量结果转换为流速；
- 将流速转换为 L/min 流量；
- 零流偏置补偿；
- 温度补偿；
- 嵌入式滤波和异常值剔除；
- 累计体积计算；
- 结构化 UART 数据输出；
- MATLAB 与嵌入式的 Golden Vector 对比测试。

因此，当前阶段**不需要推倒重写底层超声波/TDC 算法**，但需要补齐上层水表应用算法和主循环调用。完成后，后续标定工作才可以主要通过调整参数、重新编译和烧录完成。

## 3. 当前工程实际运行内容

当前主程序位于：

```text
target/main.c
```

主函数当前主要执行：

1. 看门狗初始化；
2. 系统时钟初始化；
3. GPIO 初始化；
4. UART 初始化；
5. LED 点亮、熄灭循环；
6. 通过 UART 输出 `led on` 和 `led off`。

当前主循环并没有调用超声波测量接口，也没有进行流量计算。因此，直接烧录当前 Demo 后，开发板不会自动输出完整的水表测量数据。

### 3.1 实物开发板接口说明

根据当前使用的实物板照片，该开发板底部有两个 USB Type-C 接口，板上丝印分别为：

```text
USART0
USART1
```

当前工程在 [UserSrc/UserUart.c](../UserSrc/UserUart.c) 中使用的是 `UART0`，并设置为 115200 波特率。因此，调试当前工程时应优先使用板上标有 `USART0` 的 USB Type-C 接口。

这里的 `USART0`、`USART1` 是板载 USB 转串口通道标识，不是普通的电源 Type-C 口。应使用支持数据传输的 USB Type-C 数据线连接电脑。

### 4.2 UART0 调试连接要求

开始串口测试前：

1. USB Type-C 数据线连接开发板的 `USART0` 接口和电脑；
2. 将背面拨码开关 `UART0_SEL` 设置为 `USB-S`；
3. 开发板上电或复位；
4. 在 Windows 设备管理器中确认新出现的 COM 口；
5. 串口工具设置为 `115200 / 8 数据位 / 无校验 / 1 停止位 / 无流控`。

当前 `UserSrc/UserUart.c` 中的配置为：

```c
UART_InitStruct.UART_BaudRate = 115200;
UART_Init(UART0, &UART_InitStruct);
```

`UART1_SEL` 只影响 UART1，当前阶段不需要依赖 UART1。若要使用板上标有 `USART1` 的 Type-C 接口，需要同时确认 UART1 是否在软件中初始化，并检查其对应拨码是否选择了 `USB-S`。

### 4.3 用 LED Demo 验证 Type-C 串口

在进行超声波算法开发之前，建议先烧录当前 LED Demo，验证通信链路：

1. 连接 `USART0` Type-C 接口；
2. 设置 `UART0_SEL = USB-S`；
3. 打开正确的 COM 口；
4. 烧录并运行当前 Demo；
5. 观察串口是否周期性输出：

```text
led on
led off
```

如果 LED 正常闪烁但没有串口输出，依次检查：

- USB 线是否为数据线；
- 是否接在 `USART0` Type-C 接口；
- `UART0_SEL` 是否为 `USB-S`；
- COM 口是否选对；
- 串口参数是否为 115200/8N1；
- COM 口是否被其他程序占用；
- 是否重新烧录了当前程序。

### 4.4 Type-C 接口与烧录的区别

板上的 Type-C 接口可能承担 USB 转串口或下载/调试通道，具体取决于接口标识、拨码状态和板载 USB-S 电路。不要仅凭 Type-C 外形判断两个接口功能完全相同。

推荐按照以下顺序操作：

```text
先用 USART0 Type-C 验证 UART0 输出
        ↓
确认电脑能收到 led on / led off
        ↓
再确认工程实际使用的烧录接口和下载工具
        ↓
最后接入超声波测量和结构化数据输出
```

如需使用 EJTAG 下载，应使用板上的 EJTAG 排针和对应调试器；如使用 USB 下载，则应以开发板说明书、下载工具识别结果和拨码配置为准。不要在未确认电源和接口定义前短接排针或改变电源选择。

### 4.1 超声波测量驱动

文件：

```text
driver/ls1d_std_measure.c

```

其中已经包含超声波测量硬件的初始化和控制代码，例如：

- `MEASURE_DefaultInit()`：默认测量模块初始化；
- `MEASURE_GateWindowInit()`：TDC 门控窗口初始化；
- 发射脉冲数量和分频配置；
- TDC 控制寄存器配置；
- 超时参数配置；
- 自动校准配置；
- AFE 接收链路配置；
- 发波、接收、比较器和 LNA 参数配置；
- 测量周期和巡航模式配置。

这部分属于**底层硬件测量算法/驱动**。

### 4.2 TDC 时间转换

文件：

```text
target/sonar.S
```

其中已经实现了多个 TDC 和时间转换函数，包括：

- `tdc_calcc`：计算 TDC 校准参数；
- `tdc_c_2_lsb`：校准参数转换；
- `tdc_tdcc`：TDC 结果转换；
- `tdc2time`：将 TDC 原始结果转换为时间格式；
- `tdc1517_2ps`：将内部时间格式转换为皮秒；
- `dtofcalc`：处理顺流和逆流测量结果并计算平均时差。

其中 `dtofcalc` 已经包含以下底层处理逻辑：

```text
读取顺流和逆流结果
        ↓
TDC 结果转换
        ↓
分别计算顺流、逆流 TOF
        ↓
计算时差
        ↓
对多次结果求平均
```

注意：这部分主要输出的是 TOF、时差或内部时间结果，并不是最终的流量值。

### 4.3 测量寄存器和硬件参数

文件：

该文件包含：

这些内容主要用于控制 LS1D 的超声波测量外设。

## 6. MATLAB 仿真算法与嵌入式代码的对应关系

MATLAB 仿真目录：

```text
matlab_sim/
```

### 6.1 TOF 转流速

文件：

```text
matlab_sim/algorithms/time_to_velocity.m
```

使用的精确反解公式为：

```text
v = L / (2*cos(theta)) * (1/t_down - 1/t_up)
```

其中：

- `L`：声程长度；
- `theta`：安装角；
- `t_down`：顺流传播时间；
- `t_up`：逆流传播时间；
- `v`：流速。

嵌入式端需要使用与 MATLAB 相同的公式、方向定义和单位。

### 6.2 流速转流量

文件：

```text
matlab_sim/algorithms/velocity_to_flow.m
```

计算过程为：

```text
截面积 = pi * 管径^2 / 4
流量 = 流速 * 截面积 * 流速剖面修正系数
```

最终再将 `m^3/s` 转换为 `L/min`。

### 6.3 滤波和异常值检测

文件：

```text
matlab_sim/algorithms/filter_measurement.m
```

当前 MATLAB 端支持：

- 中值滤波；
- 均值滤波；
- 一阶 IIR 滤波；
- 滑动窗口中位数；
- MAD 异常值检测；
- 无效数据标记。

嵌入式移植时建议优先实现：

```text
物理范围检查 + 异常值剔除 + 一阶 IIR 滤波
```

不建议一开始就在 LS1D 上移植复杂的大窗口排序算法。

### 6.4 累计体积

文件：

```text
matlab_sim/algorithms/integrate_flow.m
```

MATLAB 端支持：

- `skip`：无效点跳过；
- `hold`：保持上一有效流量；
- `interpolate`：前后有效点插值。

嵌入式端可以先实现简单的梯形积分，并对连续无效数据设置超时保护。

## 7. 推荐的实施步骤

### 阶段一：先验证底层超声波测量

目标：确认开发板能够正确得到原始测量结果。

需要完成：

1. 在主程序中初始化超声波测量模块；
2. 启动一次测量或进入巡航测量模式；
3. 读取顺流和逆流 TDC 结果；
4. 调用已有 TDC 时间转换函数；
5. 判断超时、无效和异常状态；
6. 通过 UART 输出原始数据。

建议 UART 输出格式：

```text
MEASURE,timestamp_ms,tof_down_ticks,tof_up_ticks,temperature_c,valid_down,valid_up,status
```

示例：

```text
MEASURE,0,67500,68200,20.50,1,1,VALID
MEASURE,250,67505,68195,20.50,1,1,VALID
```

这一阶段不要急于计算流量，先确认原始 TOF 是否稳定、方向是否正确、有效率是否足够。

### 阶段二：移植 TOF 到流速算法

在确认原始 TOF 正常后，增加：

1. TDC tick 到秒的转换；
2. 通道零点偏置补偿；
3. 顺流、逆流 TOF 合法性检查；
4. 精确流速反解；
5. 正负流向判断。

建议函数形式：

```c
int calculate_velocity(const measurement_data_t *data,
                       float *velocity_m_s);
```

### 阶段三：移植流量和滤波算法

增加：

1. 管道截面积计算；
2. 流速剖面修正系数；
3. 异常值检测；
4. 一阶 IIR 或小窗口中值滤波；
5. 输出流量单位转换。

建议函数形式：

```c
int calculate_flow(float velocity_m_s, float *flow_l_min);
float filter_velocity(float velocity_m_s, uint8_t valid);
```

### 阶段四：增加累计体积

根据真实时间戳计算：

```text
delta_volume = flow_m3_s * delta_time_s
```

然后累加得到累计体积。

需要注意：

- 时间戳必须单调递增；
- 处理时间戳溢出；
- 连续无效数据不能无限保持旧流量；
- 反向流量是否允许抵扣累计体积，需要根据产品定义决定。

### 阶段五：Golden Vector 验证

运行：

```matlab
cd('D:\WorkSpace2\上海电机学院\龙芯智能水表\5、LS1D-DEV-005-基于VScode的开发板例程\demo-window\demo-window\1.gpio_led_control_demo\matlab_sim');
run('..\测试方案\test_phase2_hardware.m');
```

脚本会生成 MATLAB 基准数据。然后将相同的：

- `tof_down_ticks`；
- `tof_up_ticks`；
- 温度；
- 有效标志；

输入嵌入式算法，比较：

- 流速；
- 流量；
- 有效标志。

建议误差目标：

```text
流速误差 < 0.1%
流量误差 < 0.1%
```

如果误差超过 1%，优先检查单位、tick 周期、方向、偏置和定点溢出。

## 8. 参数标定和重新烧录流程

### 8.1 MATLAB 参数只影响仿真

修改：

```text
matlab_sim/config/default_config.m
```

只会影响 MATLAB 仿真和 CSV 回放，不会自动修改开发板程序。

### 8.2 开发板参数必须同步到 C 代码

确定参数后，需要同步到嵌入式配置文件，例如：

```c
#define TDC_TICK_PERIOD_NS  1.0f
#define PIPE_DIAMETER_MM    20.0f
#define SOUND_PATH_MM       100.0f
#define INSTALL_ANGLE_DEG   45.0f
#define FILTER_ALPHA        0.15f
```

然后执行：

1. 修改 C 代码或头文件；
2. 重新编译工程；
3. 检查编译和链接结果；
4. 烧录开发板；
5. 重新采集 UART 数据；
6. 使用 `replay_csv` 回放分析；
7. 与 MATLAB 和标准流量计对比。

### 8.3 优先标定的参数

建议按以下顺序：

1. TDC tick 周期；
2. 顺流和逆流通道零点偏置；
3. 管径；
4. 声程；
5. 安装角；
6. 流速剖面修正系数；
7. 温度补偿系数；
8. 滤波参数。

滤波参数不能代替物理参数标定。测量值如果“很稳定但整体偏差很大”，应该先标定物理参数，而不是继续加大滤波强度。

## 9. 根据测试现象选择优化方向

| 测试现象 | 优先检查 | 处理方向 |
|---|---|---|
| 有效率低于 85% | 门控窗口、超时、换能器信号 | 优化 TDC 门控和硬件配置 |
| 平均值稳定但误差很大 | 管径、声程、角度、tick 周期 | 标定物理参数和 TDC 标度 |
| 零流时流量不为零 | 通道固定偏置 | 增加零流偏置补偿 |
| 流量偶发尖峰 | TDC 异常值、气泡、干扰 | 增加异常值检测和 IIR 滤波 |
| 响应过慢 | 窗口太大、IIR alpha 太小 | 减小窗口或增大 alpha |
| 温度变化后误差变大 | 声速温度模型 | 重新标定温度补偿 |
| 累计体积偏小 | 无效点全部跳过 | 优化无效点积分策略 |
| 累计体积偏大 | 无效时保持旧值时间过长 | 限制 hold 时间 |
| 正负方向相反 | 顺流/逆流映射错误 | 修正 TOF 通道对应关系 |
| MATLAB 与 C 不一致 | 单位、初值、定点转换 | 重新执行 Golden Vector 验证 |

## 10. 推荐的最小实现范围

为了尽快从 LED Demo 过渡到可测试的水表程序，建议先实现以下最小功能：

```text
1. 超声波测量初始化
2. 顺流/逆流 TOF 读取
3. 有效标志和超时判断
4. TDC tick 转秒
5. 零流偏置补偿
6. TOF 转流速
7. 流速转 L/min
8. 简单 IIR 滤波
9. UART 输出 CSV
```

第一版可以暂时不实现：

- 复杂自适应滤波；
- 多项式温度模型；
- 复杂插值积分；
- 多级状态机；
- 高级异常分类。

先保证原始测量、计算公式、数据输出和 MATLAB 对比闭环正确，再逐步增加功能。

## 11. 最终判断

当前工作区的算法结构可以概括为：

```text
已有：

超声波硬件控制
    ↓
TDC 读取和时间转换
    ↓
顺流/逆流 TOF 及其时差处理

尚需补充：

TOF → 流速
    ↓
流速 → 流量
    ↓
异常检测和滤波
    ↓
累计体积
    ↓
UART 结构化输出
```

因此：

> 当前不需要重新设计超声波 TDC 底层算法，但需要将已有底层测量接口接入主循环，并补齐水表应用层算法。完成应用层算法后，后续才可以主要通过参数标定、重新编译和重新烧录来优化系统。
